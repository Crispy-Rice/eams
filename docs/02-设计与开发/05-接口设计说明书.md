## 1. 概述

基础路径：`http://127.0.0.1:8000`。业务接口 31 个（加根路径共 32 条路径），在线文档 `/docs`（Swagger）可交互调试。

## 2. 统一响应格式

```
成功：{"code": 0, "msg": "提示信息", "data": <数据>}
失败：{"code": <HTTP状态码>, "msg": "错误信息", "data": null}
```

- `code = 0` 表示成功
- 错误 `code` 为对应 HTTP 状态码：400（业务校验）/ 404（资源不存在）/ 422（参数校验）/ 500（服务器内部）

> 说明：系统**无鉴权**（教学演示），除 `/auth/*` 外所有接口可直接访问，无需携带 token。

## 5. 查询与分页参数

| 接口 | 参数 | 类型 | 说明 |
|------|------|------|------|
| `GET /xxx/all` | keyword | string | 按名称模糊查询（LIKE），可选 |
| `GET /students/page` | keyword | string | 按姓名模糊查询，可选 |
| `GET /students/page` | page | int | 页码，默认 1 |
| `GET /students/page` | page_size | int | 每页条数，默认 10（钳制 1~100） |

分页返回示例：
```json
{"code": 0, "msg": "成功", "data": {"total": 6, "items": [{"id": 1, "name": "张三", ...}]}}
```

## 6. 典型请求/响应示例

### 6.1 登录
```
# 1) 先获取图片验证码
GET /auth/captcha
200 {"code": 0, "msg": "获取验证码成功",
     "data": {"token": "a1b2c3...", "image": "data:image/png;base64,...."}}

# 2) 登录（携带验证码 token 与用户输入的验证码，不区分大小写）
POST /auth/login
{ "username": "admin", "password": "admin123",
  "captcha_token": "a1b2c3...", "captcha_code": "X9K2" }

200 {"code": 0, "msg": "登录成功",
     "data": {"user_id": 1, "username": "admin", "role": "admin", "student_id": null}}

# 验证码错误或已过期
400 {"code": 400, "msg": "验证码错误或已过期", "data": null}
```
说明：验证码一次性使用（校验后即失效），5 分钟内有效；登录失败需重新获取。

### 6.2 参数校验失败
```
POST /auth/register   （缺字段）

422 {"code": 422, "msg": "参数校验错误", "data": [{"type":"missing","loc":["body","username"],...}]}
```

### 6.4 新增学生
```
POST /students/add
{ "name": "张三", "gender": "男", "age": 18, "grade": "高一", "class_id": null, "teacher_id": null }

200 {"code": 0, "msg": "新增成功", "data": {"id": 7}}
```
